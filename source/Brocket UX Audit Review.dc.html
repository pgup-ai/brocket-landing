Brocket · MVP UX audit — review pass

Keep the contracts. Collapse the ceremony.

The supplied audit is accurate as a component-status record of the working branch, but it documents surfaces — it does not judge the journey. Reconciled against pgup-ai/brocket @ codex/preview-timeline-playback (c0e8d7c), the engineering contracts (immutable versions, source lineage, preview honesty, fail-closed redaction) are the product's strongest asset. The UX debt is structural: a 14-field form before value, a pipeline exposed as buttons, and a review surface arranged as a document instead of a workspace.

A

Executive verdict

  1. Already working. The state machine is honest and rare for an MVP: staleness tracking (firstCutIsCurrent), immutable versions, per-scene source lineage, preview-vs-render honesty copy, fail-closed redaction, guarded async. Preserve all of it.
  2. Also working. The visual base already avoids AI-slop: flat slate surfaces, 1px borders, one blue, no gradients or glows. DESIGN.md is a real system document. This is a tuning job, not a redesign.
  3. Largest onboarding problem. NewProject.tsx renders the full 14-field ProjectInputsForm (template, aspect ratio, font, captions, intro, outro, 3 brand colors, CTA…) before the user has uploaded anything — front-loading Month-3 brand config and contradicting PRODUCT_VISION's "first screen after login" spec.
  4. Second onboarding problem. The pipeline is exposed as manual ceremony: upload, then an "Analyze recording" button state, then "Create first cut". The default journey should be upload → first cut with zero clicks between, with manual controls only on failure.
  5. Largest workspace problem. Review is a vertical document: five equal rounded-xl cards inside a 1024px column (max-w-5xl), preview capped at ~660×480px. On an editing display, most pixels are empty slate and the video — the product — is a minority element.
  6. Most important de-slop change. One status voice per event. Today an upload prints "Recording uploaded. Analysis queued." at page level and "Analysis queued" in the source card; render state appears in both the Preview rail and the Renders card. Consolidate, and rename vague verb targets ("Edit inputs", "Edit clicks").
  7. Color direction. Keep the slate workspace; do not introduce a new hue. Fix the real defects: slate-500 text fails AA on both backgrounds (4.2:1 / 3.7:1), blue is over-assigned (up to five blue primaries visible at once), and there is no explicit focus-ring or AI-attribution token. Chosen: Graphite + Cobalt (§E).
  8. Target layout. One two-pane review workspace (§F): dominant preview + transport left, one right rail with Scenes / Privacy / Versions tabs, Video details demoted to a collapsed drawer, exactly one primary action — Export — in the header. No multi-track timeline for the MVP.
  9. AI interaction. The evidence is already in the data (scene.source.reason, transcript indices, ranges) but rendered as jargon chips. Surface it as "Why this moment?" and concrete corrections ("Shorten", "Remove scene"); defer chat-style revision commands to the Month-5→2 agent loop.
  10. Sequence discipline. Everything in "Now" (§I) is client-side IA, copy, and layout — no schema or API changes, no discarded behavior. The plan's Month-4 editable timeline stays scoped as a correction escape hatch, per POSITIONING_DECISION.

C

Persona task flows — shortest path to export

One shared workflow, two depths. The spine is identical for both personas; the difference is what stays folded. Steps marked ✕ exist today and should be removed from the default path.

PMM / product marketer — "get me a usable video"
  1. New project → pick a goal (template), paste notes. Two decisions.
  2. ✕ Configure aspect, font, captions, intro, outro, 3 colors, CTA (becomes defaults, editable later)
  3. Upload the recording — analysis and the first cut run automatically.
  4. Watch the preview; fix wording on a scene; accept the rest.
  5. Export → copy the share link.

Never needs to see: source ranges in ms, normalized coordinates, transcript provider, timeline version IDs, render presets. Sees instead: "Why this moment?", "Cut was made before your latest changes", "Video ready".

DevRel / technical founder — "fast, but show your work"
  1. Same steps 1–3 (same shell, same defaults).
  2. Expands evidence: source in/out ranges per scene, selection reason, transcript provider — via the same "Why this moment?" disclosure.
  3. Uses exact controls: ms redaction fields, click-marker placement, transition per boundary.
  4. Compares v12 → v13 before export; then Export.

Progressive-disclosure points (fold, don't fork): evidence popover on scene cards · "Advanced" block inside Privacy (exact ms/% fields, kept — the drag + field parity in RedactionCanvas is a model pattern) · Versions tab · click-style picker behind the transport's overflow.

Where paths must stay shared: project creation, upload, preview, scene review, privacy confirmation, export, sharing — one surface, one vocabulary. Where disclosure is appropriate: anything expressed in units the renderer needs but a human doesn't (ms, %, version IDs, presets, providers). Disclosure means "collapsed in the same place", never a separate mode or product.

E

Chosen color system — Graphite + Cobalt

The current palette is Tailwind slate + blue-600 used ad hoc (DESIGN.md §2). The audit question is not "which new palette" but "which defects to fix while keeping it". Three candidates were compared; one is chosen. This report's own chrome is rendered in the chosen system.

1 · Status quo

Keep everything as-is. Rejected: ships two real defects — slate-500 body-size text below AA, and blue meaning "primary action", "current step", "active segment", "queued status" and "selection" simultaneously.

CHOSEN
2 · Graphite + Cobalt

Same slate scale and hue economy; roles made explicit. Text floor raised to slate-400; blue split into action (600) / hover (500) / selected + focus (400); AI attribution reuses the blue family. Zero new hues, zero re-theming cost.

3 · Warm graphite + signal amber

Stone neutrals with an amber action color. Rejected: amber already means "recoverable warning" across the product; repurposing it as the action color breaks a working semantic, and re-tokenizing every border/text tier buys no user value. (The violet-gradient "AI product" treatment was excluded outright.)

Why this serves both audiences without becoming an NLE

The novice's whole task — watch, tweak wording, export — is the default surface; every technical affordance (ms fields, ranges, versions, click markers) stays one disclosure deep in the same spot, so the technical user gets precision without a mode switch and the novice never pays for it. There is no track model, no clip dragging, no keyframes: corrections stay bounded verbs against an AI-owned cut, which is exactly the "directing an editor, not operating a program" principle in the README.

Prioritized implementation sequence

Aligned to the 12-month plan as amended by POSITIONING_DECISION (revision loop pulled from Month 5 toward Month 2; Month-4 timeline stays an escape hatch; lineage UI is a named Month-6 milestone). Nothing below discards working behavior or touches the timeline/render contracts.

Now — client-only, before wider alpha exposure no API/schema changes · G1, G2, G6, G7, G8, G11–G13, G20, G21 + §H
  • 1. Creation diet + upload-first (G1, G2). Acceptance: a new user reaches a playing first cut with ≤3 decisions (goal, notes, file) and no brand/aspect/typography fields on the path; server receives defaults unchanged.
  • 2. Auto-chain (G6). Acceptance: zero clicks between upload-complete and first-cut-visible on the happy path; failed/stale states keep one retry action each; no orphaned "Analyze" buttons on the happy path.
  • 3. Two-pane review workspace (G11–G14, G8): full-width project page, preview + transport left, tabbed rail right, Video details drawer, single Export panel. Acceptance: preview ≥60% of viewport width at 1440px; exactly one #2563EB element per state; render trigger/status/download/share in one panel; existing scene/text/duration/transition edits and click markers all reachable.
  • 4. Status + copy pass (G7, G9, G10, §H). Acceptance: no event announced in two places; one polite live region; every state shows one explanation + one action; §H strings shipped verbatim or better.
  • 5. A11y floor (G20, G21). Acceptance: automated contrast scan reports no text below AA; visible 2px focus ring on every interactive element; chrome animations disabled under reduced motion.

Dependencies: none between items except 3→4 (copy lands in the new layout). Measure: time-to-first-preview (target < 3 min from login on a 3-min recording, excluding upload bandwidth) and the plan's own moat metric — % of first cuts edited rather than discarded.

Next — once the first-cut loop is validated small API additions · G15, G17, G22, Tella-pattern
  • 1. Evidence popover ("Why this moment?") from existing reason/range/transcript data (G15). Acceptance: ≥50% of alpha users open it unprompted — the POSITIONING kill-criterion-2 instrument.
  • 2. Concrete correction chips: Shorten this section (exists: duration edit), Remove this scene (needs a scene-removal patch op), Use a different moment (needs a source-range patch op). Dependency: extends updateTimelineScenes; each apply = one immutable version with lineage.
  • 3. Privacy prominence (G17): rail count badge + pre-export nudge when detections exist. Acceptance: a project with detections cannot reach Export without the count being on screen.
  • 4. "Tighten quiet moments" suggestion from stored silence/idle evidence (Tella adapt). Dependency: patch-suggestion endpoint; preview-before-apply; refusal keeps baseline (mirrors the Month-2 patch-provider contract).
  • 5. Keyboard transport (G22) + relative-time version labels (G18).
Later — plan months 5–9, unchanged order agent + team capabilities
  • Revision commands with patch preview ("make this faster", "zoom when the table updates") rendered as a reviewable suggestion queue — the Underlord-pattern seat is the rail's future 5th tab. Dependency: Month-5→2 agent loop; every command emits a validated timeline-IR patch (POSITIONING §4d contract).
  • Named/restorable versions, approvals, comments (Months 7–8) — the Versions tab grows restore + approval gates; export gating moves from convention to policy.
  • Channel variants + brand components (Month 6) inside the Export panel (30s LinkedIn / 60s launch / 90s walkthrough as sibling versions with shared lineage — White Space 5).
  • Escape-hatch timeline (Month 4 scope, kept minimal): drag-trim on the segmented scrubber only — still no tracks, no keyframes.
The one recommendation

Keep the Graphite + Cobalt slate system exactly as it is — with the slate-400 text floor, a real focus ring, one blue action per view, and blue-family AI attribution — and rebuild the project page as a single two-pane guided review workspace: preview + transport left, one tabbed rail (Scenes · Transcript · Privacy · Versions) right, Video details in a drawer, Export as the only primary action; creation shrinks to goal + notes + recording with the pipeline auto-chained. It is the layout the code's own contracts are already shaped for — the audit's five surfaces slot into it without losing a feature — and it is deliberately not a manual editor, because the first cut and the confidence to approve it are the product.
